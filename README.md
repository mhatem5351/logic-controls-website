# Logic Controls website

Multilingual marketing and lead site for **Logic Controls**, an industrial automation company in 6th of October City
(Giza, Egypt): PLC / HMI / SCADA programming, control panels, machine automation, retrofits, commissioning.
Live at **https://logic-controls.com**.

Two audiences: local factories (Arabic first) and foreign manufacturers setting up plants in Egypt (English, Chinese,
Turkish). Every page exists in **4 locales**: `en`, `ar` (RTL), `zh` (Simplified Chinese, `zh-Hans`), `tr`.
The site is a static build with a tiny Worker in front. Hosting is on Cloudflare's free tier: the domain is the
only paid item, so never turn on a paid Cloudflare or third-party feature.

## Stack

| Layer | What |
|---|---|
| Site | [Astro 7](https://astro.build) static output (`build.format: "directory"`, trailing slashes), TypeScript strict, no UI framework: small vanilla-JS islands |
| Styling | Tailwind CSS 4 (Vite plugin), design tokens in `src/styles/global.css`, motion in `src/styles/motion.css`, print in `src/styles/print.css` (its own `media="print"` sheet) |
| Images / fonts | `astro:assets` + sharp (AVIF / WebP / JPEG), self-hosted Montserrat + Alexandria (fontsource), a 5 KB Turkish subset |
| Hosting | Cloudflare Workers static assets (`wrangler.jsonc`), custom domain, `public/_headers` (CSP, HSTS, caching) and `public/_redirects`. Each page also carries a hash-based CSP `<meta>` (see "Client scripts and CSP") |
| Worker | `worker/index.ts`: `/` redirects to the visitor's language (cookie, then `Accept-Language`); `/api/rfq` takes the quote form (size / type guard, honeypot, field validation, attachment count / size / type, Turnstile, file-signature check, then `send_email` to the owner's inbox); `/api/evt` records one anonymous click count. Every other path is a free static-asset hit (`run_worker_first: ["/", "/api/*"]`) |
| Forms / anti-spam | Cloudflare Turnstile + Email Routing `send_email` binding |
| Analytics | Cloudflare Web Analytics (beacon loads on the production hostname only) |
| Tests | Vitest 5 (unit), Playwright Test 1.63 (E2E, chromium + webkit), axe-core, html-validate, custom static checks, GitHub Actions |

### Client scripts and CSP

- **One module per page.** `src/scripts/site.ts` is the only client entry (loaded once by BaseLayout). Component
  `<script>`s stay in their components and are pulled in with `import "~/components/X.astro?lc-script"`
  (`integrations/site-scripts.mjs`): bundled into the site module (header, drawer, menus, copy buttons, motion switch,
  floating button…), or as their own chunk through `site-load.ts`: `now()` (at once, only on pages with the element:
  the quote form, page scripts), `idle()`, `near()` (within 1000 px of the viewport or on first touch / focus) and
  `afterLoad()`. A component script that site.ts does not list still works, but Astro bundles it on its own: the
  build warns (unless site.ts names it in an `lc-own:` comment) and, as a separate module, it fails the `modules`
  budget (an exact count). So list every new component script in site.ts.
- **Motion.** `src/scripts/motion/motion-pref.ts` is the single source of truth for "motion off" (the OS
  reduced-motion setting and the site's "Pause animations" toggle; both set `html[data-motion="off"]`). An ESLint
  `no-restricted-syntax` rule rejects a raw `matchMedia("(prefers-reduced-motion…)")` anywhere in `src/` except
  motion-pref.ts and BaseLayout's pre-paint head script. CSS `@media` blocks are not affected.
- **CSP.** Two policies, both enforced by the browser: the `public/_headers` header (origins; its `script-src` keeps
  `'unsafe-inline'` only because a header cannot list per-page hashes) and a per-page `<meta>` whose `script-src` has
  no `'unsafe-inline'`, so only the build's own inline scripts run. Astro emits the `<meta>` (`security.csp`);
  `integrations/csp-inline-hashes.mjs` then rewrites it on every built page with the SHA-256 of exactly the inline
  scripts that page contains (`is:inline` included) and moves it right after `<meta charset>`. It fails the build when
  a page has inline scripts but no CSP `<meta>`, more than one `<meta>`, a `<meta>` without `script-src`, or
  `'unsafe-inline'` in `script-src`. Build only: `astro dev` has no CSP `<meta>`.

## i18n model

- URLs are `/{lang}/<ascii-slug>/` in every locale. `/` has no page: the Worker sends a 302 to the right language,
  checking the `lang` cookie first (set by the language switcher), then `Accept-Language` (q-values; `zh-TW` → `zh`),
  then English. `hreflang` alternates for the 4 locales plus `x-default` are on every page and in the sitemap.
- Copy lives in `src/i18n/messages/<locale>/<namespace>.json`. **English is the source of truth.** Every other locale
  must have exactly the same keys and array lengths, with no empty strings or `TODO`s, and only Latin letters that the
  shipped Montserrat subsets contain. `scripts/check-i18n.mjs` enforces all of this and fails the build.
- Strings are plain text. Render them through `src/lib/text.ts`, which escapes and applies the per-locale rules:
  `heading()` for headings, card titles and FAQ questions (adds Turkish soft hyphens), `html()` for body text,
  `plain()` for attributes and `<title>`, `cleanText()` for JSON-LD. Codes such as `S7-1200` or `IEC 60204-1` never
  wrap; Latin runs in Arabic text sit in `<bdi dir="ltr">` (a parenthesised gloss keeps its brackets inside); Chinese
  breaks only between words, and a number stays with its measure word; ` · ` separators stick to the item before them.
- Language-neutral facts (slugs, years, technologies, zones) live in `src/data/`. Translations reference them by slug.
- Writing and translation rules: `src/i18n/CONTENT.md`. Terminology: `src/i18n/GLOSSARY.md`.

### Budgets

`tests/static/check-budgets.mjs` measures `dist/` and fails on any value above `tests/static/budgets.json`. Per page
type (the worst page of the type over all four locales): `html` (gzip), `beforeMain` (gzip HTML before `<main>`),
`elements`, `css` (gzip screen stylesheets), `stylesheets` (render-blocking `<link>`s), `modules` (external module
scripts: one, the site module), `js` (gzip, with its static imports; lazy chunks and Turnstile not counted) and
`images` (bytes a 412 px @2.625x phone and a 1440 px desktop would pick from each srcset, the larger of the two). Per
file: the largest CSS, JS, font, image and video. Hard checks with no budget: no chained static import in a module, a
`<head>` preload for every hero photo, speculation rules on every page, a version (`-v3`…) in every `public/media/`
file name.

`npm run test:budget -- --update` re-baselines to the current values plus headroom: bytes +5 % (rounded up to
0.5 KB), element counts +3 %, request counts (`modules`, `stylesheets`) exact. Re-baseline only for intended growth,
review the diff, add a line to `notes` in `budgets.json` and a one-line reason in the commit message. Otherwise the
ratchet quietly absorbs creep.

### CI

`.github/workflows/ci.yml` runs on pushes to `main`, on pull requests, weekly (Monday 03:00 UTC) and on manual
dispatch. It skips docs-only changes and cancels a run when a newer push supersedes it. One job on `ubuntu-24.04` with
Node 24 runs `npm ci`, `npm run lint` + `tsc -p worker`, `npm run build` (Astro's image cache is restored first),
`npm test`, `npm run test:budget`, installs the Playwright browsers (cached), writes `.dev.vars` with the public test
secret, then runs the E2E suite with 2 workers and 1 retry: pushes and pull requests run `chromium-desktop` only; the
weekly and manual runs run all three projects. A "Flaky E2E tests" step lists every test that passed only on retry
in the run summary (and as a warning). The Playwright report is uploaded only on failure. There is no deploy step and
no Cloudflare secret in CI. Per the workflow header, a warm push run takes about 12 minutes and the weekly
cross-browser run about 25, inside the 2,000 free minutes a month GitHub Free gives private repos. Because pushes
skip the phone projects, run `npm run test:e2e` (all three) locally before a release.

## Deploy

```sh
set -a; source .env; set +a        # CLOUDFLARE_API_TOKEN / CLOUDFLARE_ACCOUNT_ID for wrangler
npm run deploy                     # gate → build → dist checks → budgets → wrangler deploy (Worker + assets, custom domain)
npm run indexnow                   # after content changes
```

`npm run deploy` runs `scripts/predeploy.mjs` first, which refuses to deploy when the working tree has uncommitted
changes (override: `ALLOW_DIRTY_DEPLOY=1`, not recommended), when page dates are stale (`content-dates.mjs --check`),
or when `check-i18n` or the unit tests fail. Then it builds, runs `tests/static/check-dist.mjs` and `npm run
test:budget` on the very files it uploads, and runs `wrangler deploy`. The slow suites (`astro check`, E2E) are the
release checklist's job.

The production Turnstile secret is a Worker secret (`npx wrangler secret put TURNSTILE_SECRET`). Plain vars
(`OWNER_EMAIL`, `MAIL_FROM`, `ALLOWED_HOSTNAMES`) and the `send_email` destination live in `wrangler.jsonc`. The
destination must be a verified Email Routing address. A Cloudflare redirect rule sends `www` to the apex domain.

### Page dates (content-dates)

Sitemap `<lastmod>` and case-study `datePublished` / `dateModified` come from `src/data/content-dates.json`, not from
git or the build time. Each page is dated by a hash of its own copy subtree, data record and project photos
(`scripts/content-dates.mjs` header lists what counts); templates, nav, `common.json`, `ui.json` and `seo.json` never
re-date a page.

- After any copy, data or photo edit: `node scripts/content-dates.mjs --write` and commit
  `src/data/content-dates.json` in the same commit.
- `--check` lists stale pages and exits 1 (predeploy runs it); `--bootstrap` rebuilds the file from git history
  (refuses on a shallow clone).
- A stale page still builds: it is dated at build time, with one warning, so a change is never understated.
- After deploying content changes: `npm run indexnow`.

### Release checklist

1. On a fresh `npm run build`: `npm run lint`, `npm run typecheck:worker`, `npm test`, `npm run test:budget` and
   `npm run test:e2e` (all three projects) are green.
2. `node scripts/content-dates.mjs --check` passes (or `--write` and commit).
3. `npm run deploy`.
4. Live spot-check on https://logic-controls.com: home, one case study and contact, in en and ar. The browser console
   is clean, with no Content-Security-Policy violation. Send a test form only when appropriate (it emails the owner).
5. `npm run indexnow` if content changed.
6. After enabling ANY Cloudflare dashboard feature, re-check the live console for CSP violations: a feature that
   injects inline scripts (Rocket Loader, Bot Fight Mode's JavaScript detections, Zaraz…) is refused by the per-page
   `<meta>` policy (see `public/_headers`).
7. Every January: rebuild and deploy. The footer's © year is `new Date().getFullYear()` at build time
   (`src/components/Footer.astro`), with no runtime JS.

## Click counts (WhatsApp, call, email, quote)

Cloudflare Web Analytics counts page views only. Clicks on the contact channels are counted separately, without
cookies or any identifier: `src/scripts/analytics.ts` sends one beacon per click to `POST /api/evt`, and the Worker
writes one data point to the **Workers Analytics Engine** dataset `lc_clicks` (binding `CLICKS` in `wrangler.jsonc`).
Workers Free includes 100,000 data points written and 10,000 read queries a day; data is kept for three months. A page
view sends at most 8 events (a repeat of the same click within 3 s is dropped), and every `/api/evt` call also counts
against the Worker's 100,000 requests a day. Nothing is sent under Do Not Track / Global Privacy Control or in
`astro dev`. The Worker validates the event (`parseEvt` in `src/lib/rfq-rules.ts`), drops cross-site or oversized
posts, and always answers 204. `form-sent` is dispatched by the form script after a successful send (a no-JS post is
not counted).

| Column | Value |
|---|---|
| `blob1` | kind: `whatsapp`, `call`, `email`, `copy-email`, `quote`, `form-sent` |
| `blob2` | placement: `header`, `drawer`, `hero`, `band`, `fab`, `footer`, `form`, `contact`, `thanks`, `body` |
| `blob3` | locale: `en`, `ar`, `zh`, `tr` |
| `blob4` | page path, e.g. `/ar/services/control-panels/` |

Query it with the SQL API (an API token with **Account Analytics: Read**; the account ID is in `.env`):

```sh
curl -s "https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID/analytics_engine/sql" \
  -H "Authorization: Bearer $CLOUDFLARE_ANALYTICS_TOKEN" \
  --data "SELECT blob3 AS locale, blob1 AS kind, blob2 AS placement, SUM(_sample_interval) AS clicks
          FROM lc_clicks
          WHERE timestamp > NOW() - INTERVAL '7' DAY
          GROUP BY locale, kind, placement
          ORDER BY clicks DESC
          FORMAT JSONEachRow"
```

Use `SUM(_sample_interval)` rather than `COUNT()`: Analytics Engine may sample at high volume. Compare `form-sent`
with WhatsApp / call clicks per locale to see which channel each audience prefers.

## Content rules (honesty)

The site makes only claims the client can back up. In short (the full rules are in `src/i18n/CONTENT.md`):

- Brands are "platforms we program and integrate", **never** "partner", "authorized" or "certified". Panels are
  "designed following IEC 60204-1 / IEC 61439 practice", never "certified" or "compliant". Batch control is "structured
  following ISA-88 principles". No UL / CE certification, no 24/7 promise, no stock or warehouse.
- **No named clients**: case studies are anonymised. Third-party logos and nameplates are cropped or blurred in photos
  and videos. Never glob `client-data/` from `src/`, because the raw photos contain them.
- Numbers come from the client (50+ projects, 4+ years). Never add figures, percentages, results or client names that
  are not in the English source. Use Western digits in every locale, including Arabic. Show **no founding year**
  anywhere. Projects delivered before the company existed say "delivered by our engineers before the company was
  established".
- The founder's past employers are described, never named. Sub-sectors from the team's past jobs are "our engineers'
  experience", not Logic Controls case studies.
- The zones list is a coverage statement ("we work across…"), not a list of past project sites. Map distances are
  labelled straight-line.
- Chinese and Turkish documentation is "on request". On `zh` pages, email replaces WhatsApp as the main channel,
  because WhatsApp is blocked in mainland China.
